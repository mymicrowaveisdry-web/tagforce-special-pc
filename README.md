# Yu-Gi-Oh! ARC-V Tag Force Special Decomp

A C# reconstruction and reverse-engineering project for Yu-Gi-Oh! ARC-V Tag Force Special on PSP. It decodes card data and assets and implements a growing native duel model. The finished application will require a user-provided, legally acquired ISO; no game assets are distributed.

## Decompilation

No original game function has been rebuilt and verified byte for byte yet. This repository currently builds a C# reconstruction, not a matching PSP executable. The original main executable is `NPJH00142`'s `EBOOT.BIN`.

```powershell
dotnet restore ygo-tag-force-special-decomp.slnx --locked-mode # pinned SDK in global.json + dependency locks
dotnet build ygo-tag-force-special-decomp.slnx --no-restore   # build the C# reconstruction
dotnet test ygo-tag-force-special-decomp.slnx --no-build --no-restore
dotnet run --project TagForceSpecial.Tools --no-build -- duel-demo # synthetic cards only
```

A PSP byte-matching toolchain and a `make match` equivalent have not been implemented. Passing C# tests, decoding assets and exporting Ghidra pseudocode do not establish executable byte matches.

## Updating progress

```powershell
dotnet run --project TagForceSpecial.Tools --no-build -- progress         # refresh from the recorded inventory
dotnet run --project TagForceSpecial.Tools --no-build -- progress --check # detect a stale generated section
dotnet test ygo-tag-force-special-decomp.slnx --no-build --no-restore --logger 'trx;LogFileName=progress.trx' --results-directory TestResults
dotnet run --project TagForceSpecial.Tools --no-build -- progress --test-results TestResults/progress.trx
```

Update the function registries when analysis identifies more candidates, and refresh research snapshots in `config/progress.json` after validating new evidence. Original executable hashes and analysis-export hashes identify the three current inventory sources; registry body lengths are analysis metadata, not match evidence.

[The progress workflow](.github/workflows/progress.yml) runs on pushes, pull requests, manual dispatch and weekly on Monday at 07:17 CET / 08:17 CEST (06:17 UTC, Europe/Berlin). It regenerates progress using actual test results. On the default branch it commits changed README/validation snapshots; pull requests receive a generated report artifact. Scheduled updates become active after the workflow is merged into the default branch, with Actions enabled and permission for the update job to push. Protected branches may require adapting the update job to your repository policy.
