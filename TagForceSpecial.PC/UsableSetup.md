# Local import and supported deck editor

Launch the PC application to open the WPF workbench and import the original English v2.1 ISO or its complete extracted folder. Recognition, structural checks and exact build support remain separate; other builds and CSO cannot provide game-ready data. Include recipes is enabled by default and discovers a compatible local prepared library; uncheck it to skip recipes. Pinned PSP menu/card fonts are installed automatically; optional source overrides are available in the workbench. The [WPF workbench](../docs/importer/USER_GUIDE.md) provides richer browsing and diagnostics.

Import runs in a worker with measured or indeterminate progress. Cancel requests safe cancellation. Repeat import validates the source and reuses checked outputs. Completion lists each result; Play Game requires a usable catalog and presentation. Clean previous importer data previews owned paths and requires confirmation; recipes must be carried forward first. Decks, fonts, profile and unrelated preferences remain intact.

Default data root: `%LOCALAPPDATA%/TagForceSpecial`; `--data-root <folder>` isolates a run. Presentation output must be outside Git worktrees. The game reads `import/active.json` and its pinned session manifest, using immutable outputs under `import/stages/`. Historical reports and diagnostics remain under `import/sessions/`. The old cache/journal layout is no longer consumed; see [architecture](../docs/importer/ARCHITECTURE.md).

In the PC deck editor, up/down selects a card, right/left adds/removes, Tab/Y changes Main/Extra/Side, and Enter/A opens actions for name/search/filter/save/load/play. Invalid drafts can be saved but cannot launch. Deck revisions remain separate from imported resources. Original-game Deck Edit menus use their own displayed controls.

The pool is `ConfirmedCardPool`: registered effect-family cards except Tokens. Main requires 40–60 cards, Extra and Side at most 15 each. Same-name catalog records share copy limits under the strictest applicable built-in EBOOT restriction. Save/DLC overrides, story progression and unimplemented cards remain unsupported. Saved decks retain identity, catalog and regulation checks; no mutable duel state is persisted.

Preferences keeps input bindings, scaling, opponent seed and selected revision, with a recoverable backup. Import and verification failures leave the previous active import available. Select the exact original source and repeat import to repair changed derived outputs; editing their manifest hashes does not satisfy trusted catalog/presentation pins. Original assets and sources remain local and read-only.
